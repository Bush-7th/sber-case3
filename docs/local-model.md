# Переход на локальную модель

**Статус:** инструкция для будущего стенда по specs, не проверенный запуск. Backend, Compose и модельные адаптеры в этом checkout отсутствуют. A должен дополнить файл точными командами и результатом реального вызова.

1. A поднимает API/worker/PostgreSQL и Ollama с постоянным volume. Проверяет доступность Ollama из worker; сервис не публикуется наружу.
2. Загружает `qwen3-vl:4b-instruct` как первоначального кандидата. Например, на установленном Ollama: `ollama pull qwen3-vl:4b-instruct`. Точный образ, модель и хеш фиксируются после совместимого запуска.
3. В серверной конфигурации вне Git устанавливает `MODEL_PROVIDER=local`, `LOCAL_*` адрес/модель по итоговым Settings. Точные имена `LOCAL_*` в specs пока не зафиксированы.
4. Перезапускает процессы способом из будущего Compose. Локальный профиль не требует ILONS_API_KEY/OLMOCR_API_TOKEN и не вызывает удалённые сервисы при отказе.
5. Специалист создаёт новый run в UI. Старый run сохраняет прежний provider/profile. Новый показывает invocation metadata локального вызова.
6. На небольшом реальном документе сверяет поля и источник, измеряет время/память на CPU. При недоступных удалённых сервисах повторяет локальный прогон.
7. Для возврата выбирает `MODEL_PROVIDER=external`, проверяет независимые параметры olmOCR/Qwen и создаёт новый run.

Меньшая модель допустима для демонстрации переключения. Равное качество/скорость с Qwen не заявляются. Разница в приватности: внешний профиль передаёт подготовленный контент внешним сервисам, локальный — работает через Ollama. Реальная точность по восьми видам и потребление памяти остаются непроверенными.
