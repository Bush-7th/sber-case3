# LOC01 — локальный Ollama на CPU

M06 [OllamaProvider](../backend/src/app/modules/inference/ollama.py) реализует тот же DocumentModelPort M05, что и Qwen. Выбор находится в M15 [build_document_model](../backend/src/app/runtime/container.py). Local не создаёт Qwen/OCR-клиенты и не требует их ключей/доступности. Ошибка локальной модели не вызывает отправку документа удалённому сервису или переключение модели.

## Версия, модель и запуск

Ollama закреплена на 0.12.10: прежняя 0.12.3 не соответствует требованию qwen3-vl не ниже 0.12.7 из [официальной карточки модели](https://ollama.com/library/qwen3-vl:4b-instruct). В [Compose](../compose.yaml) закреплён проверенный digest образа, CPU-настройки, одна одновременно загруженная модель/один запрос, очередь не более двух и постоянный ollama-data. Порт Ollama на хост не публикуется. Healthcheck подтверждает ответ API, но не анализ документа.

Веса загружаются явно один раз. Для анализа нужны уже локально сохранённые веса; приложение их не скачивает. Два проверяемых профиля:

| Модель | Manifest digest | Размер весов по локальному API |
| --- | --- | --- |
| qwen3-vl:4b-instruct | sha256:ee4b975b58c17ce268cd19d40db35d5edc64603035d2ffc1fee1968eb0947f7b | около 3,30 ГБ |
| qwen3-vl:2b-instruct | sha256:ea422f1e73652a95479954d8572d3c8c6022f628ce2d38a1a04aae1b7f2d5300 | около 1,89 ГБ |

Начальный CPU-профиль после сравнения — 2B; 4B остаётся явным альтернативным профилем. Используется локальный instruct-вариант. Cloud-имена и remote_host/remote_model в метаданных запрещены до генерации. Адрес клиента допускает localhost, сервис ollama или частный IP, без credentials/query. HTTP-прокси из окружения не наследуется, перенаправления запрещены. Это ограничения нашего адаптера; глобальный флаг OLLAMA_NO_CLOUD в закреплённой 0.12.10 не поддержан и не выдаётся за работающую настройку.

```bash
docker compose --profile local up -d ollama
docker compose --profile local exec ollama ollama pull qwen3-vl:2b-instruct
docker compose --profile local exec api python -m app.runtime.local_cli inspect
docker compose --profile local exec api python -m app.runtime.local_cli sample <FILE_VERSION_UUID> --page 1 --unload
```

API должен быть запущен по [runtime.md](runtime.md); sample использует уже сохранённый оригинал от OCR01. Для изображения/сканированной страницы используется только локальная модель. Явная диагностика vision на нативном PDF: добавить `--rasterize`; он рендерит выбранную исходную страницу и не вызывает olmOCR.

Для запуска вне Docker можно скачать [официальный Linux-релиз 0.12.10](https://github.com/ollama/ollama/releases/tag/v0.12.10). Проверенный SHA-256 ollama-linux-amd64.tgz — `8f4bf70a9856a34ba71355745c2189a472e2691a020ebd2e242a58e4d2094722`. В текущей проверке CPU-компоненты распакованы без системной установки в игнорируемый local-data/ollama; веса и журналы также исключены из Git. Первый запуск Ollama создаёт стандартные служебные файлы пользователя. Не использовать tmpfs для многогигабайтного каталога весов на ограниченной RAM.

```bash
OLLAMA_HOST=127.0.0.1:11439 OLLAMA_MODELS=/absolute/path/to/models OLLAMA_NUM_PARALLEL=1 OLLAMA_MAX_LOADED_MODELS=1 CUDA_VISIBLE_DEVICES=-1 ROCR_VISIBLE_DEVICES=-1 ollama serve
OLLAMA_HOST=http://127.0.0.1:11439 ollama pull qwen3-vl:2b-instruct
LOCAL_BASE_URL=http://127.0.0.1:11439 uv run --project backend python -m app.runtime.local_cli inspect
```

## Настройки и переключение

Настройки приведены в [.env.example](../.env.example). Основные ограничения:

```dotenv
MODEL_PROVIDER=local
LOCAL_BASE_URL=http://ollama:11434
LOCAL_MODEL=qwen3-vl:2b-instruct
LOCAL_MODEL_DIGEST=sha256:ea422f1e73652a95479954d8572d3c8c6022f628ce2d38a1a04aae1b7f2d5300
LOCAL_TIMEOUT_SECONDS=300
LOCAL_CONTEXT_WINDOW_SIZE=16384
LOCAL_MAX_OUTPUT_TOKENS=2048
LOCAL_MAX_INPUT_BYTES=12000000
LOCAL_MAX_RESPONSE_BYTES=4000000
LOCAL_NUM_THREADS=6
LOCAL_KEEP_ALIVE_SECONDS=30
LOCAL_IMAGE_MAX_SIDE=1280
```

Пустой LOCAL_MODEL_DIGEST позволяет получить digest установленного тега при создании нового профиля; заданный digest обязан совпадать. При выборе другой модели менять обе настройки. Профиль фиксирует модель/digest, версию сервера, prompt/schema hashes, CPU threads/контекст/дедлайн/лимиты и keep_alive. Перед анализом и после него проверяются метаданные; изменение тега/версии не публикует результат прежнего профиля.

Во всех модельных запросах options.num_gpu=0, temperature=0, seed=0, think=false и stream=false. Runtime-настройки меняют только новые вызовы; профиль уже созданного запуска неизменяем. GPU не включается скрыто. `/api/ps` показывает size_vram и размер/контекст модели; size — отчёт сервера, а не измеренный RSS процесса. `--unload` освобождает модель после диагностики. Сбой очистки не скрывает исходный результат/ошибку.

Чтобы выбрать внешний режим, задать MODEL_PROVIDER=external и подтверждённые QWEN_* / ILONS_API_KEY по [qwen.md](qwen.md), перезапустить API/будущий worker для новых запусков. Для standalone-проверки использовать qwen_cli. Общая фабрика выбирает ровно один адаптер; local_cli отвергает external вместо изменения выбора. Полный пользовательский переключатель и запуск очереди появятся в INT01; сейчас API бизнес-операции остаются 501, readiness pipeline=false.

## Содержимое, этапы и источники

Нативные текст/адресованные ячейки поступают без OCR. Для PNG/JPEG или сканированной PDF-страницы M03 готовит [ограниченное изображение](../backend/src/app/modules/assets/local_preparation.py): EXIF-ориентация, белый фон прозрачности, сохранение пропорций, максимум LOCAL_IMAGE_MAX_SIDE, PNG. Исходный blob не меняется; версия преобразования и исходная страница сохранены. Координаты областей не добавляются. Реальная Office-подготовка/табличные стратегии относятся к FMT01.

Локальный вызов выполняет последовательные этапы:

1. Для изображения — транскрипция текста локальной VLM; для нативного текста этот этап отсутствует. Пустой транскрипт — явная ошибка без удалённого OCR.
2. Классификация фрагментов с источниками и проверяемыми цитатами. Unknown не запускает извлечение; закреплённый человеком тип сохраняет независимый predicted_type.
3. Извлечение по nullable-схеме только выбранного вида, с явными русскими смыслами полей. M05 валидирует JSON, цитаты/покрытие источников и нормализует строки той же политикой, что и Qwen.

Схемы передаются в format по [API Ollama](https://docs.ollama.com/api/chat), [Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs). [Промпты](../backend/src/app/modules/inference/prompts/local-classify-v1.txt) и смысл полей версионированы; их общий hash входит в профиль. Имя/расширение файла не передаются модели, tools отсутствуют. Каждый HTTP-запрос делает одну попытку; автоматического повторения невалидного JSON нет.

Native/OCR-цитата проверяется по подготовленному тексту. Для vision цитаты проверяются по машинной локальной транскрипции и ведут к исходной странице с extraction_method=vision, без OcrResult ID или выдуманного bbox. Это проверка согласованности с транскрипцией, не независимое доказательство точности чтения пикселей. PreparedSource с транскриптом возвращается для последующего сохранения M03 в INT01; CLI пока его не сохраняет. Все данные/значения/цитаты/изображения скрыты из repr/stdout/логов.

Вне заявления дополнительный applicant_inn требует в проверенной цитате метки ИНН и роли заявителя/получателя субсидии. Неподписанный номер сертификата не становится ИНН; сохраняется как неподтверждённое наблюдение с normalized=null и unknown role. Null и unreadable не превращаются в ноль/успех; правила и решения человека остаются отдельными.

UTF-8 размер текстового входа ограничивается консервативно относительно num_ctx минус num_predict; для vision дополнительно резервируются image tokens. Большой фрагмент явно отвергается local_context_too_large, без скрытого усечения. Это начальная защита, не независимое измерение токенизации изображения или вместимости всех документов. Разбиение большого файла/сборка документов подключаются в FMT01/INT01.

## Устойчивость и текущая проверка

Ошибки имеют provider=ollama и коды local_*. Сеть/тайм-аут, 429/5xx retryable с Retry-After; отсутствующие веса (404), cloud/неподдержанная capability, неверный профиль, слишком большой вход/контекст, пустая транскрипция и невалидный JSON/цитаты автоматически не повторяются. M11 позже ограничит временные попытки тремя и обеспечит heartbeat/lease. Сам адаптер повторов, установки весов и внешнего fallback не делает. Транзакция чтения оригинала закрывается до модельных запросов.

Метаданные содержат длительность и input/output hashes каждого этапа, счётчики токенов при наличии, версии подготовки и профиль. Chain of thought, тело ошибок, исходное исключение HTTP-драйвера, значения и ключи не выводятся.

**Фактическая проверка 10.10.2026:** AMD Ryzen 5 7430U, 12 логических CPU, около 16 ГиБ RAM, 6 threads. Сохранённая первая страница реальной выписки ЕГРН cfc95813-a134-4c1a-a2db-69b74eff3b88. Qwen/OCR ключи были пустыми, их адреса — недоступными. 4B определила property_document и выдала валидируемые поля/цитаты: около 274,6 секунды (114,1 классификация + 160,2 извлечение). `/api/ps` size_vram=0; журнал — 0/37 слоёв GPU, RSS наблюдался около 5,6 ГиБ. После обнаружения ошибочного дополнительного ИНН добавлена общая проверка роли; этот ранний результат не выдаётся за полную предметную приёмку.

Полноразмерный PNG-рендер на 4B достиг тайм-аута 300 секунд; RSS около 7,8 ГиБ. Введено ограничение изображения. 2B без смыслов полей классифицировала источник за полный цикл около 68,7 секунды, но вернула все поля null: это не успешная проверка минимума. После добавления русских смыслов полей 2B выполнила нативный цикл за 99,8 секунды (32,0 классификация + 67,6 извлечение): cadastral_number/purpose/address known, applicant_inn missing/null, area unreadable/null. JSON/цитаты прошли проверку; size_vram=0. Invocations: ранний 4B — 79fea216-25ea-4b87-9b2d-b638bf83eb9e, успешный 2B — f7cf88d4-a2b9-42df-9449-55f2f4c186fe. 2B выбрана новым явным default, без скрытого fallback; это не доказательство качества всех видов. Последующие результаты изображения — в collaboration.md.

Контрактные тесты проверяют CPU/options/format, native/vision этапы, источники/nullable поля/роль ИНН, неизменяемый профиль/digest, отсутствие remote settings/fallback, тайм-аут/лимиты/ошибки и преобразование изображения. Они используют только HTTP-ответы и bare pixels/facts; качество реальных документов не доказывают. Все реальные документы, веса и результаты остаются вне Git, синтетические документы не используются.

Docker build/up и совместный расход памяти всего Compose не проверены из-за доступа к daemon (BL06). Стратегии Office, все реальные виды/форматы, worker/очередь/правила/UI, сохранение local vision-транскрипта и предметная проверка B остаются впереди. Скорость и точность локального режима не приравниваются к удалённому Qwen.
