# Передача фронтенда разработчику A

Дата: 10.10.2026. Ветка B: `frontend/UI01`. Основа — specs §9. **Это предварительный контракт потребителя; OpenAPI и согласование A отсутствуют.** Фронтенд не имитирует работающий сервер, не содержит тестовых данных в рабочей сборке и не обращается напрямую к OCR/Qwen.

## Источник типов

`frontend/src/shared/api/contracts.ts` содержит DTO и Zod-проверки фактических ответов. `client.ts` — единственный транспортный адаптер. После получения OpenAPI нужно сопоставить/сгенерировать типы и изменить этот адаптер. Ответ, не соответствующий схеме, показывает ошибку совместимости.

Все ID — строки, Decimal-значения — строки или null; даты — ISO. Результаты правил приходят с сервера. Null не заменяется нулём. Контекст применимости хранится как `true / false / unknown`. Источники имеют file_version_id, страницу или sheet/cell_range, способ native/ocr, пометку производного представления и цитату при наличии. Координаты областей фронтенд не создаёт.

Списки: `{items: [...], next_cursor: string | null}`. Список заявок загружается по 25 строк с продолжением. Поиск фильтрует уже полученные страницы, это указано в подписи. Справочные списки предполагают полный небольшой каталог; поддержку их pagination нужно согласовать, если он вырастет.

## Уточнения поверх списка endpoints specs §9

| Вопрос | Предложение B, требует подтверждения A |
| --- | --- |
| Восстановление сессии | GET `/sessions` → `{user:{id,name,role}, csrf_token}`. 401 означает отсутствие сессии; POST возвращает ту же схему; DELETE → 204 |
| Список видов для правки типа/admin | GET `/document-types` → items `{id,name,extension}`. В рабочем режиме не использовать seed как fallback |
| CSRF | `X-CSRF-Token` из подтверждённой сессии, same-origin cookies. Вход защищается Origin/SameSite на сервере; точный bootstrap согласовать |
| Листы таблицы | `/files/{id}/sheets/_first` означает первый доступный лист; ответ `{sheet,sheets,cells:[{address,value,formula}]}`. Затем каждый лист выбирается явно |
| Превью страницы | GET `/files/{id}/preview?page=N`; оригинал отдельно `/content`. Выдача и вложенный viewer требуют серверных прав |
| Повтор файла | POST `/packages/{id}/verification-runs` принимает optional `retry_file_version_id`; общий run всё равно охватывает весь состав |
| Сохранение черновика | PATCH `/admin/program-drafts/{id}` принимает name/requirements/rules и expected_row_version целиком. Endpoint правки одного правила пока не используется |
| История | GET package содержит `decisions` и `report_history` со ссылками на run, revision, created_at |
| Решение | POST decisions возвращает сохранённый Decision; не меняет input_revision и machine verdict |

Прочие пути соответствуют specs §9. Тела команд описаны в `client.ts`. expected_revision и expected_row_version обязательны; optimistic concurrency проверяет сервер. Ключ загрузки и её исходная expected_revision сохраняются при потере ответа и повторе, меняются при изменении набора файлов. Ключи остальных команд сохраняются в памяти по SHA256 запроса при сетевом сбое/5xx/непроверяемом ответе; успешный ответ или определённый отказ освобождает ключ. Перезагрузка страницы не сохраняет незавершённое намерение; если ответ команды потерян, прежде чем повторять после перезагрузки, нужно сверить состояние на сервере.

При 409 формы сохраняют введённые данные, серверные запросы обновляются; пользователь сверяет актуальную ревизию перед повторным действием. При 401 защищённый query cache очищается, приложение возвращается к входу. Политика автоматического retry HTTP в Query/Mutation отключена: повтор модели принадлежит worker.

## Серверные требования интеграции

1. Реализовать конечные DTO, авторизацию всех endpoints и файлов, CSRF и быстрый надёжный приём файлов.
2. Поддержать текущую/историческую ревизию, progress_version и частичные результаты. Не возвращать pass при partial/provisional/failed.
3. После правки типа/состава/контекста/редакции возвращать новый input_revision и run; сохранять старые отчёты/решения.
4. Проверять черновик и публиковать новую неизменяемую версию. Условный дефицит не может получить error.
5. Валидировать и импортировать `catalogs/seed.json`; развернуть шаблоны правил в конкретные привязки.
6. Добавить frontend в Compose: build context `./frontend`, порт 80, доступный upstream `api:8000`. Общий Compose принадлежит A. Настроить ограничения загрузки на API/reverse proxy; `client_max_body_size 0` здесь делегирует лимит API, не задаёт нормативный размер.

Браузерные контрактные тесты подменяют HTTP только внутри Playwright. Они проверяют поведение UI, но не подтверждают OCR, модель, хранение, авторизацию backend или реальную приёмку документов.
