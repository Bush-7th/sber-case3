Все экраны используют `client.ts`, который вызывает типизированный `openapi-client.ts`; прежние HTTP DTO больше не отправляются и не принимаются.

## Граница API и модели экрана

`adapters.ts` преобразует DTO CON01 в локальные модели React из `contracts.ts`; ответы проверяются Zod. Administrative ProgramDraft/RuleDefinition используют сгенерированные типы напрямую. Внутренние названия `context`, `document_units`, `name` не являются HTTP-контрактом. Деньги остаются строками, неизвестные значения — null, результаты правил вычисляет сервер.

## Конфликты и неоднозначные ответы

401 удаляет защищённый query cache и возвращает ко входу. 409 перечитывает защищённые данные, сохраняя session query, локальные правки и исходную ревизию формы. Применение актуальной ревизии требует явной сверки; решение после этого подтверждается заново. Admin предлагает загрузить актуальный черновик после сверки.

Idempotency-Key обязателен для upload/verify/decision/publish. Ключи JSON-команд хранятся по SHA256 намерения, без текста пароля/документа в Map; успешный проверенный ответ освобождает ключ, определённый 4xx отказ позволяет исправить намерение. Потеря ответа/5xx/непроверяемый ответ сохраняет ключ. При неоднозначном сохранении решения блокируется изменение формы, повтор передаёт первоначальное тело и ключ, даже если polling уже обновил отчёт. Автоматические повторы Query/Mutation отключены. Перезагрузка не сохраняет незавершённые намерения; до повторной команды нужно сверить состояние сервера.

У CON01 нет batch item ID для сопоставления принятых и отвергнутых файлов. Поэтому совпадающее имя в одном batch отклоняется до отправки с объяснением; файл можно переименовать или загрузить отдельно. Имя используется только для сопоставления квитанции, не для классификации документа.

## Что требуется от A для совместной приёмки

1. Подключить прикладные обработчики вместо 501, каталог и полные проверки правил.
2. Выдавать актуальность, частичные результаты, источники, фрагменты, имена листов и аудит по CON01; сохранённые отчёты возвращать через run ID.
3. Проверять доступ к каждому ресурсу и файлу, CSRF и optimistic concurrency.
4. Добавить frontend в общий Compose: build `./frontend`, upstream `api:8000`; проверить Docker build/up и сохранность volumes.
5. Отдельно согласовать восстановление сессии/CSRF. B не добавлял endpoint за пределами контрактов A.

Проверки UI с подменой HTTP используют конечные DTO CON01. Они не подтверждают импорт каталога, обработку реальных документов, OCR/LLM, серверную арифметику или полную приёмку стенда.
