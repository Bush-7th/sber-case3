# QWN01 — Qwen и серверная валидация извлечения

M05 задаёт [DocumentModelPort и схемы](../backend/src/app/modules/recognition/model.py), общие [машинные факты](../backend/src/app/modules/recognition/facts.py) и [валидацию/нормализацию](../backend/src/app/modules/recognition/validation.py). M06 реализует [QwenProvider](../backend/src/app/modules/inference/qwen.py), M15 — явную фабрику и серверную диагностику. Публичные endpoints и OpenAPI 0.2.0 остались прежними. Извлечение пока запускается CLI; очередь, сохранение FileAnalysis, сборка документов, правила и UI подключаются следующими задачами.

## Проверенное подключение

10.10.2026 с предоставленным пользователем ключом проверены:

- GET `/v1/models`, `Authorization: Bearer <ILONS_API_KEY>`: 200, модель `Qwen/Qwen3.8-27B` присутствует.
- POST `/v1/chat/completions`: JSON с `model`, `messages` ролей system/user, `temperature=0`, `max_tokens`, `stream=false`. Проверенный режим `response_format={"type":"json_object"}` запрашивает JSON; предметная схема задаётся промптом и валидируется сервером.
- Успешный ответ: application/json, `model`, один элемент `choices`, `finish_reason=stop`, `message.role=assistant`, строка `message.content`. Reasoning и дополнительные поля провайдера не сохраняются и не выводятся. ID сервиса проходит ограничение длины/символов.

Это проверка используемого подмножества API, а не полная совместимость со всеми OpenAI endpoints/параметрами. JSON Schema в response_format, streaming, vision и tools для этого адаптера не заявляются. GET `/health` с этим ключом вернул 403; `/openapi.json` — 404. Они не служат проверкой готовности генерации. Контекст 262000 и фактические лимиты сервиса остаются неподтверждёнными.

```dotenv
QWEN_BASE_URL=https://llm.ilons.ru
QWEN_MODEL=Qwen/Qwen3.8-27B
QWEN_CONTEXT_WINDOW_SIZE=262000
ILONS_API_KEY=
QWEN_GENERATION_PATH=/v1/chat/completions
QWEN_API_FORMAT=openai-chat
QWEN_AUTH_HEADER=Authorization
QWEN_AUTH_SCHEME=Bearer
QWEN_TIMEOUT_SECONDS=300
QWEN_MAX_OUTPUT_TOKENS=8192
QWEN_MAX_INPUT_BYTES=750000
QWEN_MAX_RESPONSE_BYTES=4000000
```

300 секунд — общий клиентский дедлайн и сетевой тайм-аут одной попытки. Остальные ограничения — настройки приложения, не подтверждённые серверные пределы. Размер входа ограничивается UTF-8 байтами промпта/схемы/содержимого; это не подсчёт токенов и не доказательство вместимости контекста. Ответ читается с ограничением размера. Настройки находятся в `.env.example`; настоящий ключ — только в игнорируемом `.env`/окружении сервера, отдельно от OCR-токена.

Профиль неизменяем и включает URL/путь/формат/модель, prompt_version/hash, schema_hash и клиентские ограничения. Вызов с другим профилем отвергается до HTTP. Источники копируются до ожидания сети. Метаданные вызова содержат ID/correlation ID, хеши входа и ответа, длительность и версии подготовки, без ключа, текста или chain of thought. Local startup не создаёт Qwen-клиент и не вызывает удалённые сервисы; CLI явно выбирает Qwen для диагностики.

## Извлечение и происхождение

В схеме есть восемь основных видов, отдельное оговорённое расширение ГИМС и unknown. По каждому фрагменту сохраняются независимые predicted_type/effective_type, источники и цитата классификации. Закреплённая правка типа требует извлечения именно выбранной схемы; без правки типы должны совпадать. Сборка логического документа и разрешение конфликтов между фрагментами остаются INT01.

Все ключи полей выбранного вида обязательны. Отсутствующие поля возвращаются как null; backend создаёт missing с normalized=null. Найденное поле содержит исходную строку raw и ссылки `{source_id, excerpt}`. Модель не получает имя файла, расширение, UUID оригинала, порядок загрузки или право создавать координаты. Она видит только адресованные текстовые источники и forced_type при наличии. [Версионированный промпт](../backend/src/app/modules/inference/prompts/extract-v1.txt) трактует содержимое как данные и запрещает выполнение инструкций из документов.

Неполный JSON, Markdown-обёртка, повторяющиеся JSON-ключи, NaN/Infinity, неизвестные поля, неверные типы и пропущенные ключи отвергаются. Все источники должны быть покрыты, все цитаты — встречаться в соответствующем входном тексте, raw — в каждой своей цитате. При проверке допускается только свёртка пробельных символов. Неизвестный source_id или придуманный фрагмент не принимается.

SourceLocation создаёт сервер: исходные file_id/version и известная страница либо sheet/cell. EvidenceRef сохраняет native/ocr, а для OCR — ID прежнего OcrResult. Координаты модель не выдаёт. При нескольких источниках каждое значение сохраняет свои проверенные ссылки. ИНН заявителя и гаранта имеют разные subject_role.

M03 [преобразует HTML-таблицы OCR в видимый текст](../backend/src/app/modules/assets/text_projection.py) перед моделью: границы строк/ячеек становятся пробельными символами, HTML entities раскрываются, script/style не входят в текст. Это явная версия `ocr-html-visible-text-v1`; текст без HTML-таблиц сохраняется без изменения с `ocr-text-identity-v1`. Исходный OCR в БД не перезаписывается. Цитаты проверяются по этому подготовленному входу, а ссылка ведёт к оригиналу и сохранённому OCR. Версии подготовки входят в invocation metadata; преобразование не является новым OCR-вызовом.

Десятичные значения нормализуются строками через Decimal без float, округления или расчёта правил. Поддерживаются числовые строки с десятичной точкой/запятой и однозначными пробелами групп разрядов. Даты YYYY-MM-DD/DD.MM.YYYY проверяются по календарю и переводятся в ISO. Неоднозначное число, погрешность/диапазон, неподдержанная дата или число с единицей остаются unreadable с исходной строкой и источником; normalized=null. Запрашиваемая субсидия не выводится как расходы минус собственные средства. Минимум полей и бизнес-вердикт этот адаптер не вычисляет.

## Ошибки и повторы

Ошибки имеют provider=qwen, stage extracting/validating и correlation ID. Они отделены от preparing/ocr; тело ответа и текст исключения HTTP-драйвера не выводятся.

| Ситуация | Код | Автоматический повтор |
| --- | --- | --- |
| Сеть / общий или сетевой тайм-аут | qwen_network_error / qwen_timeout | Допустим, планирует M11 |
| 429 / 5xx | qwen_rate_limited / qwen_service_error | Допустим с Retry-After |
| 401/403 | qwen_auth_error | Нет |
| 400/415/422 / 413 | qwen_unsupported_input / qwen_input_too_large | Нет |
| Редирект/неожиданный envelope/слишком большой ответ | qwen_invalid_response / qwen_response_too_large | Нет |
| Невалидный JSON/схема/цитата, пустой ответ, finish_reason не stop, другая модель или tools/refusal | qwen_invalid_model_output | Нет |
| Несовпадающий закреплённый профиль | qwen_profile_mismatch | Нет |

Для ошибок JSON/схемы/источника reason — безопасная категория invalid_json/invalid_schema/invalid_provenance. Клиент делает одну попытку. Максимум три временные попытки, задержки, heartbeat и защита поздней публикации подключаются M11 в INT01. Сбой Qwen не меняет сохранённый OCR; повтор использует прежний текст.

## Диагностика и фактическая проверка

Нужны зависимости и PostgreSQL по [runtime.md](runtime.md), исходник/версия или OcrResult от [OCR01](ocr.md). CLI закрывает транзакцию подготовки до HTTP. Команды выполняются на сервере:

```bash
uv run --project backend python -m app.runtime.qwen_cli models
# Нативный текст одной страницы уже сохранённого оригинала:
uv run --project backend python -m app.runtime.qwen_cli sample <FILE_VERSION_UUID> --page 1
# Сохранённый OCR, без нового OCR-вызова:
uv run --project backend python -m app.runtime.qwen_cli sample <FILE_VERSION_UUID> --ocr-result-id <OCR_RESULT_UUID>
# Повторное извлечение закреплённого типа:
uv run --project backend python -m app.runtime.qwen_cli sample <FILE_VERSION_UUID> --ocr-result-id <OCR_RESULT_UUID> --forced-type property_document
```

CLI выводит только метаданные, имена найденных/отсутствующих/нечитаемых полей и тип. Значения, цитаты, ключ и reasoning не печатаются. Если нативного текста нет, CLI просит сначала подготовить OCR и выбрать его ID; он сам OCR не запускает. При выборе OCR ID проверяется исходная версия. Диагностика пока не сохраняет FileAnalysis и не создаёт пользовательский отчёт.

**Реальный прогон 10.10.2026:** пользователь явно разрешил Qwen получить первую страницу выписки ЕГРН. Вход взят из прежнего OcrResult c0d96f13-5731-4dcb-9ffe-650ff08bc0f5, версия оригинала cfc95813-a134-4c1a-a2db-69b74eff3b88. Новый OCR не запускался. После преобразования HTML-таблицы получен property_document; JSON/схема/цитаты прошли серверную валидацию. Кадастровый номер, назначение и адрес приняты; applicant_inn=null/missing. Площадь осталась unreadable с исходной строкой и normalized=null. Успешный вызов — около 15,7 секунды, invocation ID 9069dc65-b1c5-4d54-8774-8c351785174e. На ранних пробах невалидный JSON и неподтверждённые цитаты были отвергнуты.

120 backend-тестов прошли на PostgreSQL 17.11. Они проверяют nullable-схемы всех видов, числа/даты/затраты/роли, происхождение, преобразование HTML, снимок источника, формат HTTP, тайм-ауты/лимиты, секреты и ошибки без внутренних retry. Интеграционный тест реальной БД подтверждает: после Qwen 503 и пересоздания runtime тот же сохранённый OCR используется без обращения к OCR, во время Qwen нет открытой транзакции. Модели в этих тестах заменены HTTP-ответами; реальный прогон описан отдельно. Ruff, свежесть OpenAPI и упаковка промпта в wheel проверены.

Ручная проверка B, качество всех восьми видов/семи форматов, контекст 262000, CPU Ollama, Docker, worker/очередь и OCR → Qwen → правила → UI ещё не проверены. QWN01 остаётся на проверке, ядро не принято.
