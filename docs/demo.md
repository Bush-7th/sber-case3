# Сценарий защиты B

Проводится после подключения реального backend и заполнения test-matrix. Контрактные тесты для живой демонстрации не используются.

1. Войти специалистом. Создать заявку, явно выбрать программу, редакцию и известный/неизвестный контекст.
2. Загрузить реальный пакет из нескольких форматов, включая настоящий DOC/XLS. Показать быстрый приём и первый готовый файл до окончания пакета.
3. Показать стадии OCR/извлечения, минимальные поля, источник рядом с результатом, несколько листов таблицы и условный дефицит как warning.
4. Показать отдельное правило доли на машинных числах, UNKNOWN без операнда, просроченный документ и отдельные ИНН заявителя/гаранта.
5. Исправить тип/состав, дозагрузить документ. Показать новый run/revision и исторический отчёт.
6. Зафиксировать решение с основанием; дозагрузкой показать устаревание прежнего решения.
7. Войти администратором. Клонировать редакцию, изменить 0.50→0.60, перечень и условие. Сохранить, проверить, опубликовать.
8. Вернуться специалистом и применить редакцию к тем же файлам. Показать изменившееся объяснение и сохранённый старый отчёт.
9. Вместе с A переключить server configuration на local. Выполнить новый реальный вызов без удалённых подключений.
10. Объяснить API-границу, Query и revision, почему UI не вычисляет verdict, показать изменения параметра без Python-кода.

На вопросы о непроверенных материалах, лицензиях Office и спорных bindings отвечать по limitations. Планируемое поведение не выдавать за фактически измеренное.
